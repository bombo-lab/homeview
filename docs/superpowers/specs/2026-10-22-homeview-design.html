1목적과 범위

1.1 목적

앱은 홈서버의 상태를 그래프로 보여준다. 앱은 홈서버에 연결된 인프라도 보여준다. 앱은 보기 전용이다.

1.2 범위에 포함

  1. Docker 토폴로지: compose 프로젝트, 컨테이너, 네트워크, 볼륨, 포트와 그 관계.
  2. 컨테이너 상태: 실행 상태(running, exited)와 health.
  3. 메트릭: 컨테이너와 호스트의 CPU, 메모리, 디스크 현재 값.
  4. 호스트 서비스: 실행 중인 systemd 서비스.
  5. 리스닝 포트: 주소, 소유 프로세스, 노출 범위.

1.3 범위에서 제외

  1. 제어 기능. 앱은 컨테이너를 시작, 중지, 재시작하지 않는다.
  2. 로그 보기.
  3. 앱 자체 인증. 앱은 Tailscale IP에만 포트를 연다.
  4. 메트릭 추이 그래프. 앱은 Grafana 링크만 준다.
  5. Tailscale 피어 목록.
  6. 노출 범위 레인 보기(시안 C). 10절의 후보이다.

2전체 구조

2.1 데이터 흐름

세 출처의 데이터가 앱으로 들어온다. 앱은 데이터를 토폴로지 하나로 합친다. 화면은 15초마다 토폴로지를 요청한다.

2.2 결정 사항

  1. 기존 ~/monitoring compose 파일은 수정하지 않는다. 앱은 monitoring_monitoring 네트워크에 외부 네트워크로 연결한다.
  2. 보기 전용 경계는 두 곳에 둔다. 첫째, 프록시가 POST를 차단한다. 둘째, 앱 코드에는 GET 요청만 있다.
  3. 컨테이너에 pid: host 권한을 주지 않는다. 수집기가 호스트에서 호스트 정보를 수집한다.
  4. 수집기는 임시 파일에 먼저 쓴다. 그 다음 mv로 호스트 파일을 교체한다. 그래서 앱은 반쯤 쓴 파일을 읽지 않는다.
  5. 코드 저장소는 맥의 /Users/bombo/Documents/900_PROJECT/999_homeview이다. 홈서버에는 이미지, compose 파일, 수집기만 배포한다.

4.4 포트 연결 규칙

  1. 소유 프로세스가 docker-proxy이면, 앱은 Docker 포트 매핑에서 같은 (HostIp, PublicPort)를 찾는다. 앱은 그 컨테이너에 PORT_MAPPING 엣지를 만든다.
  2. 리스너에 unit 값이 있으면, 앱은 그 서비스에 PORT_OWNER 엣지를 만든다.
  3. 소유 프로세스를 모르면, 앱은 owner를 "UNKNOWN"으로 설정한다. 화면은 "미확인"을 표시한다.

5.3 배치

  1. 화면은 노드를 섹션별 격자로 배치한다. 배치 라이브러리는 사용하지 않는다.
  2. 섹션 하나는 노드 kind 하나 또는 compose 프로젝트 하나를 담는다.
  3. 화면은 섹션을 위에서 아래로 다음 순서로 쌓는다: HOST, HOST_SERVICE, LISTEN_PORT, compose 프로젝트(이름 순서, 소속 컨테이너를 담음), 소속 없는 컨테이너(parent가 null), NETWORK, VOLUME.
  4. 섹션 하나는 최대 4열이다. 노드가 4개를 넘으면, 화면은 다음 줄에 배치한다.
  5. 카드 간격은 가로 24px, 세로 20px이다. 섹션 안쪽 여백은 20px이다. 섹션 사이 간격은 40px이다.
  6. 화면은 모든 섹션을 가장 넓은 섹션 기준으로 가운데 정렬한다.
  7. 섹션 안에서 화면은 노드를 id 순서로 정렬한다. 그래서 같은 데이터는 항상 같은 위치에 그려진다.
  8. 노드가 없는 섹션은 그리지 않는다. 필터(5.1)로 숨긴 노드도 섹션에서 뺀다.
  9. 사용자는 노드를 드래그할 수 없다. 화면은 노드 위치를 저장하지 않는다.

섹션 박스:

5.4 상호작용

  1. 사용자는 배경을 드래그해서 그래프를 이동한다. 포인터가 3px보다 많이 움직이면, 화면은 그 동작을 드래그로 판정한다.
  2. 사용자는 마우스 휠로 줌한다. 줌 중심은 포인터 위치이다. 줌 범위는 0.1배에서 3배이다.
  3. 터치 기기에서 사용자는 한 손가락으로 이동한다. 사용자는 두 손가락으로 줌한다.
  4. 화면은 오른쪽 위에 버튼 세 개를 표시한다: +, −, Fit. +는 1.2배 확대한다. −는 1.2배 축소한다.
  5. Fit은 그래프 전체가 보이도록 줌과 위치를 맞춘다. 여백은 60px이다. 최대 배율은 1.5배이다.
  6. 화면은 그래프를 처음 그릴 때 Fit을 한 번 실행한다.
  7. 데이터가 갱신되면, 화면은 현재 줌과 위치를 유지한다.
  8. 화면은 왼쪽 아래에 엣지 범례를 표시한다. 범례는 엣지 kind별 선 샘플과 이름을 보여준다.
  9. 사용자가 노드를 선택하면, 화면은 선택된 카드의 테두리를 #3182f6으로 바꾼다.
  10. 노드가 선택되면, 그 노드에 연결된 엣지의 불투명도는 기본값의 2.5배이다. 나머지 엣지의 불투명도는 기본값의 0.3배이다.
  11. 사용자가 배경을 클릭하면, 화면은 선택을 해제한다. 드래그는 선택을 해제하지 않는다.
  12. 데이터가 갱신되어도 선택된 노드가 남아 있으면, 화면은 선택을 유지한다.

5.5 상세 패널

  1. 사용자가 노드를 선택하면, 오른쪽 패널이 그 노드의 속성을 표시한다. 패널 폭은 320px이다.
  2. 패널의 맨 위에는 노드 kind와 노드 이름이 있다. kind는 섹션 색으로 표시한다.
  3. 패널은 그 노드에 연결된 엣지도 표시한다. 엣지 한 줄은 엣지 kind 배지와 상대 노드 이름이다.
  4. 사용자가 엣지 줄을 클릭하면, 화면은 상대 노드를 선택한다.
  5. 컨테이너 노드와 호스트 노드의 패널에는 Grafana 링크(http://100.94.174.67:3000)가 있다.
  6. 화면 폭이 640px 이하이면, 패널은 화면 아래에서 올라오는 시트로 바뀐다.

  1. 앱이 출처를 조회한다.

  3. 응답을 해석하지 못하면, 출처 상태는 ERROR이다.
  4. 호스트 파일의 snapshotAt이 90초보다 오래되었으면, 출처 상태는 STALE이다. 앱은 그 데이터를 계속 사용한다.
  5. 그 외에는 출처 상태가 OK이다.

7.2 이미지 배포 절차

  1. 맥에서 linux/amd64 이미지를 빌드한다.
  2. docker save로 이미지를 저장한다.
  3. 결과를 ssh homeserver docker load로 전송한다.
  4. 홈서버에서 docker compose up -d를 실행한다.

레지스트리는 사용하지 않는다.

7.3 수집기 설치 절차

  1. 스크립트를 /usr/local/bin/homeview-collect.sh에 복사한다.
  2. 유닛 파일을 /etc/systemd/system/homeview-collector.service와 .timer에 복사한다.
  3. systemctl daemon-reload를 실행한다.
  4. systemctl enable --now homeview-collector.timer를 실행한다.

수집기는 root로 실행한다. 다른 사용자의 포트 소유 프로세스를 보려면 ss -p에 root 권한이 필요하다. 호스트 파일의 권한은 0644이다.

9인수 기준 (EARS)

AC-01사용자가 tailnet 기기에서 http://100.94.174.67:3001을 열면, 앱은 compose 프로젝트별로 컨테이너를 묶은 그래프를 표시해야 한다.
AC-02앱은 각 컨테이너 노드에 실행 상태와 health를 표시해야 한다.
AC-03앱은 각 컨테이너를 연결된 네트워크와 마운트된 볼륨에 엣지로 이어야 한다.
AC-04호스트 포트가 컨테이너에 매핑되어 있으면, 앱은 포트 노드를 그 컨테이너에 잇고 노출 범위 색을 표시해야 한다.
AC-05앱은 실행 중인 systemd 서비스와 그 서비스의 리스닝 포트를 표시해야 한다.
AC-06Prometheus가 응답하면, 앱은 컨테이너별 CPU %와 메모리를 표시해야 한다. 앱은 호스트 CPU, 메모리, 디스크 사용률도 표시해야 한다.
AC-07사용자가 노드를 선택하면, 앱은 상세 패널에 그 노드의 속성과 연결 관계를 표시해야 한다.
AC-08화면이 보이는 동안, 앱은 15초마다 데이터를 갱신해야 한다. 앱은 마지막 갱신 시각을 표시해야 한다.
AC-09출처 하나가 실패하면, 앱은 나머지 출처의 정보를 계속 표시해야 한다. 앱은 실패한 출처를 배지로 표시해야 한다.
AC-10호스트 파일이 90초보다 오래되면, 앱은 호스트 출처를 STALE로 표시해야 한다.
AC-11앱은 Docker 상태를 바꾸는 요청을 보내지 않아야 한다. 프록시는 POST 요청과 DELETE 요청에 403을 반환해야 한다.
AC-12앱은 Tailscale IP 이외의 인터페이스에서 접근할 수 없어야 한다.
